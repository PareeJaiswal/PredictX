# PredictX — Predictive Maintenance System

PredictX is a machine predictive-maintenance application that uses a trained Random Forest model to classify machine sensor readings as a potential failure or no predicted failure. The Flask backend stores prediction history and failure alerts in SQLite, while the HTML/CSS/JavaScript frontend displays machine information, analytics, and alert status.

## Features

- Machine inventory with six demonstration machine profiles.
- Machine details and latest recorded prediction.
- Random Forest inference using machine type and five sensor measurements.
- Persistent prediction history in SQLite.
- Automatic failure-alert creation for a registered machine when a failure is predicted.
- Alert resolution through the frontend.
- Dashboard analytics, charts, latest prediction details, and prediction/alert history.
- Input validation for machine type and sensor values.

> **Demo-data note:** The machine names, sample sensor readings, and inventory statuses (Healthy, At Risk, Critical) are predefined demonstration profile data. Prediction outcomes are generated by the trained model from the submitted sensor readings. The predefined inventory status is not dynamically recalculated from each prediction.

## Technology stack

- **Frontend:** HTML, CSS, JavaScript, Chart.js
- **Backend:** Python, Flask, Flask-CORS
- **Machine learning:** scikit-learn Random Forest pipeline, pandas, joblib
- **Database:** SQLite
- **Dataset:** UCI AI4I 2020 Predictive Maintenance dataset (`data/data.csv`)

## Requirements

- Python 3.9 or later (use a version compatible with the installed scikit-learn model dependencies)
- pip

## Run locally

1. Open a terminal in the project root (the folder containing `app.py`).
2. Create and activate a virtual environment (recommended):

   **Windows PowerShell**
   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

3. Install dependencies:

   ```bash
   python -m pip install -r requirements.txt
   ```

4. Start the Flask application:

   ```bash
   python app.py
   ```

5. Open the application at <http://127.0.0.1:5000/>.

The Flask application serves the frontend from the `frontend/` directory. Keep the backend process running while using the application.

## API endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/` | Serves the dashboard (`index.html`). |
| GET | `/api/machines` | Returns registered machines with demonstration profile details. |
| GET | `/api/machines/<machine_id>` | Returns one registered machine and its latest prediction. |
| GET | `/api/predictions` | Returns saved prediction records. |
| GET | `/api/alerts` | Returns saved failure alerts. |
| PATCH | `/api/alerts/<alert_id>/resolve` | Marks an alert as resolved. |
| GET | `/health` | Backend health check. |
| POST | `/predict` | Validates readings, runs the model, saves the prediction, and creates a failure alert when applicable. |

### Example prediction request

Send a JSON object to `POST /predict`:

```json
{
  "machine_id": "MCH-001",
  "machine_type": "L",
  "air_temperature": 298.1,
  "process_temperature": 308.6,
  "rotational_speed": 1500,
  "torque": 40,
  "tool_wear": 20
}
```

A successful response includes the `prediction_id`, `machine_id`, `alert_id` (null when no alert is created), `predicted_failure`, and `status`.

Machine IDs must already be registered, and the submitted machine type must match the registered machine. Machine type must be `L`, `M`, or `H`. Sensor readings must be finite numeric values and satisfy the validation rules in `backend/predictor.py`.

### Example commands (PowerShell)
```powershell
# Health check
Invoke-RestMethod -Uri "http://127.0.0.1:5000/health"

# Prediction request
$body = @{
    machine_id = "MCH-001"
    machine_type = "L"
    air_temperature = 298.1
    process_temperature = 308.6
    rotational_speed = 1500
    torque = 40
    tool_wear = 20
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:5000/predict" -Method POST -ContentType "application/json" -Body $body
```

## Machine-learning pipeline

The saved model is loaded from `models/random_forest_model.pkl` when `backend/predictor.py` is imported. The training script is `notebooks/10_random_forest.py` and:

1. Loads `data/data.csv` and standardizes sensor column names.
2. Uses machine `Type` plus air temperature, process temperature, rotational speed, torque, and tool wear as input features.
3. Uses `Machine failure` as the target and excludes the failure-mode columns and identifier columns from the features.
4. Splits the data into training and test sets using an 80:20 split, `random_state=42`, and stratification.
5. Builds a preprocessing and Random Forest pipeline with 200 trees, `random_state=42`, and `class_weight="balanced"`.
6. Prints a confusion matrix and classification report, then saves the fitted pipeline to `models/random_forest_model.pkl`.

To retrain the model, run the training script from the project root:

```bash
python notebooks/10_random_forest.py
```

The model evaluation metrics should be taken from the output of the training run; this README does not claim a particular accuracy score.

## Database

The SQLite database is stored at `database/maintenance.db` by default. Set the `MAINTENANCE_DB` environment variable to use a different database file.

The application initializes the database when `app.py` starts. The main tables are:

- **machines:** registered machine IDs and machine types.
- **predictions:** sensor readings, predicted result, status, timestamp, machine ID, and optional confidence field.
- **alerts:** machine ID, related prediction ID, alert message, resolution flag, and timestamp.

Back up `database/maintenance.db` before replacing or modifying database files. The included database contains demonstration and test records.

## Tests and utility scripts

The project includes scripts for checking the model, database initialization/upgrades, prediction behavior, and saved records. Run the relevant script from the project root, for example:

```bash
python test_predictor.py
python test_database.py
```

These are standalone utility scripts; they are not a substitute for a complete automated test suite.

Run these scripts individually from the project root. Some scripts may create or modify test records in the SQLite database. Back up the database before running database-related tests.

## Deployment and security notes

The current `app.py` configuration is intended for local development. Before public deployment:

- Disable Flask debug mode.
- Use a production WSGI server rather than Flask's development server.
- Restrict CORS to the deployed frontend origin (or remove CORS if frontend and API are served from the same origin).
- Configure HTTPS and protect the database and model files.
- Do not commit secrets, local virtual environments, cache folders, or private data.

## Limitations

- The six machine profiles are predefined demonstration records, not live industrial IoT connections.
- Predictions depend on the supplied sensor readings and the trained dataset/model; they are not a guarantee of real-world machine condition.
- The current application does not ingest live sensor streams or provide failure probability/feature-importance values through its prediction API.
- Maintenance decisions should be confirmed through physical inspection and manufacturer operating guidance.
